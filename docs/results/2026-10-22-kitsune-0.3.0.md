# Kitsune 0.3.0 vs Playwright: personal-browsing rerun

[Reports](README.md) · [Previous token analysis](2026-10-21-token-efficiency.md)

## Summary

**96 agent runs completed, all externally scorable.** Kitsune 0.3.0 substantially
narrows the input-token gap against Playwright, especially with Claude Code's
`--bare` client. It does **not** establish a general success or speed advantage.
Kitsune uses fewer tool calls and about half the response text, but more model
requests and about 20% more instrumented time. Full-description runs expose
remaining `expect` usability and tab-policy problems.

## What improved, and what did not

### 1. Default token efficiency is much closer to Playwright

In the earlier bare paired cohort, Kitsune input was **+30.5%** relative to
Playwright; now it is **+4.2%**. In the earlier full-description default A/B,
it was **+33.6%**; now **+16.2%**. These are historical comparisons, not a
controlled causal estimate: the model is stochastic, cohorts have different
success sets, and the Kitsune default tool surface changed.

Compare Kitsune directly against the previous pinned `1045a5e` A/B arms:

| Client | Previous default input | Previous explicit lean input | 0.3.0 default (lean) input |
| --- | ---: | ---: | ---: |
| Bare | 1,895,677 | 1,411,006 | 1,292,342 |
| Full | 3,143,079 | 2,452,880 | 2,471,486 |

Thus input is **31.8% / 21.4% lower than the previous default**, but only
**8.4% lower / 0.8% higher than previous lean** (bare / full). Do not attribute
the entire default improvement to new result formatting or schema optimizations.
The lean default itself delivers a substantial part of the practical benefit.

The bare first request is now nearly equal between servers (4,545 vs 4,558).
It used to be approximately 4,522 vs 5,823 in the old default paired cohort.
However, previous *lean* Kitsune was 3,921; new capabilities/contracts also add
prefix weight. First-request input includes system and task text, not only tools.

### 2. Smaller results do not yet translate into fewer model requests

Kitsune native tool-response text is **48.8% / 49.3% smaller**, and agent calls
are **11.0% / 3.1% fewer**, but model requests are **16.1% / 13.1% more**.
A tool call is not a model request: multiple calls can share a request.

The input decomposition supports this distinction:

| Input component | Bare PW | Bare Kitsune | Full PW | Full Kitsune |
| --- | ---: | ---: | ---: | ---: |
| First-request prefix × requests | 763,541 | 888,705 | 1,507,577 | 1,925,045 |
| Remaining accumulated history | 477,174 | 403,637 | 619,453 | 546,441 |

Kitsune has less history input in both arms. Remaining total-input overhead is
associated with the prefix repeated over more requests, not larger tool results.
This prefix decomposition is an accounting approximation, not a captured API
payload attribution of each token to a schema field.

The new affordances are actually used, including by the truncating client:

| Kitsune feature | Bare | Full descriptions |
| --- | ---: | ---: |
| `browser_tabs(include_active=True)` | 23 | 18 |
| `browser_snapshot(text=True)` | 35 | 37 |
| Calls with nonempty `expect` | 38 | 50 |

Previously bare-mode `snapshot(text=True)` was never used. The new contract
visibility is materially better, but `browser_page_text` is still called 52/55
times and snapshots 46/52 times; redundant observation remains worth studying.

### 3. `expect` is a remaining latency and ergonomics problem

Kitsune errors by cause:

- Bare: **12 outcome timeouts**, **2 invalid expect alternatives**, 3 missing
  elements.
- Full: **14 outcome timeouts** (13 × 5 s, one × 3 s), **12 invalid expect
  alternatives**, one unsupported `visible` key, one HTTP 404 document error,
  one missing element and one stale ref.

Examples from the full-description trace:

- `browser_type(..., expect={"value":"2027-04-10"})` is rejected because an
  observation selector such as `selector` or `text` is required.
- `browser_form_fill(..., expect={"selector":"textarea, input[type=text]",
  "value_changed":true})` dispatches the fill successfully, then waits 5 seconds
  because the expected selector is not found on the resulting page.

Native agent `tools/call` durations sum to **23.5 vs 74.2 s** in bare and
**23.2 vs 82.6 s** in full (PW vs Kitsune). These sums are not wall time when
calls overlap, but the timeout counts and durations identify a concrete latency
source. They do not mean every timed-out action failed to mutate the page.

Playwright still produces many recoverable empty-CSS-selector errors (17 bare,
27 full), plus stale/malformed-ref errors. It is not error-free either.

## Failure analysis and the grading contract

| Arm | Task | Target | Failure |
| --- | --- | --- | --- |
| Bare | `pb-research-02` | Both | Saved only one of the two required source links |
| Bare | `pb-research-02` | Kitsune | Also navigated a starting tab away from its original URL |
| Bare | `pb-account-02` | Playwright | Functional answer correct; starting tab changed |
| Full | `pb-research-02` | Both | Saved only one of the two required source links |
| Full | `pb-research-01` | Kitsune | Functional answer correct; starting tab navigated to search |
| Full | `pb-tabs-04`, `pb-handoff-01`, `pb-handoff-04` | Kitsune | Functional success, starting tabs preserved, but closed an agent-created tab |

The last three fail **v1**, which prohibits every tab close. They pass the
already implemented **v2_agent_tab_cleanup** contract. This explains the full
Kitsune **19 → 22** difference; it is not three cases of closing user tabs.
Neither contract permits changing starting-tab URLs, so those failures remain.
No recorded forbidden-write action occurred in this cohort. That is not proof
that every historical wrong-target-write bug is fixed.

## Recommendations

1. **Keep lean as the default.** It delivers most of the demonstrated practical
   reduction without requiring users to discover a preset.
2. **Make `expect` easier to use correctly.** Prefer action-specific examples or
   discriminated schema alternatives, clear input-value observation semantics,
   and guidance not to wait for navigation after a same-URL save. Preserve the
   distinction between successful dispatch and an unmet postcondition.
3. **Keep tab ownership and preservation explicit.** Continue reporting v1 and
   v2 separately; starting-tab navigation is still a real protocol violation.
4. **Optimize model round trips next.** Measure whether initial active context
   and text+refs can replace follow-up reads rather than merely adding options.
5. **Repeat/counterbalance before ranking.** The observed full-description
   safety gap and ~20% timing gap need additional runs. This cohort does not
   rerun the component gallery, shadow DOM/iframe/video tests, live sites, or
   the unimplemented personal-history track.

## Reproduction

Use a clean Kitsune checkout pinned to the revision above. Each command performs
48 agent runs and can consume API credit:

```sh
uv run --locked python -m kitsune_benchmark personal \
  --harness claude-api --all --variant 0 \
  --kitsune-project artifacts/vendor/kitsune-v0.3.0 \
  --budget-usd 2 --execute

uv run --locked python -m kitsune_benchmark personal \
  --harness claude-api-full --all --variant 0 \
  --kitsune-project artifacts/vendor/kitsune-v0.3.0 \
  --budget-usd 2 --execute
```

`claude-api-full` means **full client tool descriptions**, not the Kitsune
`full` tool preset. Both runs here use Kitsune's default **lean** preset.
A single attempt, one variant, one model and fixed target order cannot establish
statistical significance, general browser robustness, or release-wide causality.
