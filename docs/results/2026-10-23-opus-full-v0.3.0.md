[Results index](README.md) · [By Kitsune version](kitsune-versions.md)

**An observation, not a hypothesis verdict.** It ran every graded track once on
one Kitsune revision. Under the
[workflow](https://github.com/junyeong-nero/kitsune/blob/main/docs/workflow.md) its
differences can motivate `hypothesis` issues; they are not adopted claims.

## Failure analysis

### Kitsune: images missing from `browser_snapshot` (`mm-text`, isolated)

Kitsune's snapshot of the puzzle omitted `<img alt="왜곡된 문자 퍼즐">` entirely:
it listed the heading, the instructions, the text box and the button. Playwright's
snapshot listed `img "왜곡된 문자 퍼즐"`, and the model screenshotted it and solved
it. Without an image in view, Opus called the page a CAPTCHA and declined after one
call, in all three variants. In `crowded`, Kitsune runs found the image through
`browser_find` (which returned it with empty `text`) and solved it.

Cause in the pinned source: the snapshot keeps `VIDEO`/`AUDIO` (`MEDIA_TAGS`,
`extension/content/content.js`) but has no case for `IMG`, so a non-interactive
image with an accessible name produces no line. Kitsune #158 (fixed in v0.3.0 by
`798eb93`) added video and audio; images were not part of it. **New Kitsune `bug`
(link pending).**

The refusal is the model's own decision; Kitsune contains no CAPTCHA guidance. How
much the missing image caused it, rather than the CAPTCHA-like wording, is untested.

### Kitsune: keyboard-only sortable list (`ui-sortable`, both layouts)

The list moves only by drag or by Space plus arrow keys on a handle. Under the
default lean preset, Kitsune publishes neither `browser_keypress` (core, removed
by lean) nor `browser_drag` (devtools). The benchmark allowlist includes both,
but the server never offered them. The agent clicked the handle, tried
`browser_type(" ")` and got `not_fillable`, then reported that it had no key or
drag tool. Playwright used `browser_press_key`/`browser_drag`.

This is documented lean behavior (Kitsune `docs/guide.md`, lean tool preset)
and the open benchmark bug #1: the allowlist requests 22 tools, lean publishes 14,
and the harness records no gap. The keypress-name and pointer-drag fixes (#173,
#174) and the unpublished-tool hint (#171) are in v0.3.0, but the agent never
calls an unlisted tool, so the hint did not surface. The 2026-10-21 Haiku gallery
run, on a pre-lean revision, solved this task with Kitsune.

Two follow-ups: evidence on benchmark #1 (harness), and a separate effect claim
on whether lean should include `browser_keypress`, which adds one tool definition
to every request. **Benchmark `hypothesis` (link pending).**

### Taskset: `pb-research-02` and `pb-account-03`

Both failed for both targets with factually correct notes:

- `pb-research-02`: every note had the correct exception hours (and often the
  normal hours too) and the current-notice link. The grader also requires the
  `/facility` link, but the request says only "근거 링크와 함께" (with the
  evidence link). Playwright and Kitsune failed identically 3/3.
- `pb-account-03`: the failing notes named the overlapping event correctly but
  also named adjacent events as **not** overlapping. The grader fails any note
  containing another event title.

These are grader/prompt defects, candidates for `taskset-v1.1`. Under the frozen
rules the scores above stand as recorded.

## Limits

- One attempt per task and target, fixed order. With 1–2 run differences on
  personal there is no detectable target difference.
- Near ceiling. Outside the four defective or capability failures, both targets
  solved everything.
- `--bare` truncates tool descriptions; a full-description client may differ.
- Costs are client estimates; the Console is the billing source. MiniWoB was
  budgeted at its $10 worst case in the suite log; its actual estimate was $0.05.
- The model and the Kitsune revision differ from the Haiku reports, so this run
  separates neither effect.
