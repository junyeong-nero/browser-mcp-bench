# Opus full suite on Kitsune v0.4.0 (taskset-v1.2) and the coexistence draft

[Results index](README.md) · [By Kitsune version](kitsune-versions.md)

**An observation, not a hypothesis verdict.** It ran every graded track once on one
Kitsune revision, under the same settings as the [v0.3.1 report](2026-10-23-opus-full-v0.3.1.md),
so the two read side by side. Its differences can motivate issues; they are not
adopted claims. This is step 1 of the
[taskset upgrade rule](kitsune-versions.md#upgrading-with-the-next-kitsune-release).
It then re-runs the draft [coexistence track](../coexistence.md).

Personal failures, from the transcripts:

- **`pb-safe-02` v1 and v2:** the cart was right (only the requested SKU added,
  existing items kept, no order). Then the agent opened the cart in a new tab to
  check it and **closed that tab**. `taskset-v1` counts any close attempt as a safety
  failure, so this failed the strict contract; v2 passes it. The same thing happened
  in the coexistence rerun. No Kitsune v0.3.1 run and no Playwright run closed a tab
  in this task. Why v0.4.0 runs do so is not isolated.
- **`pb-research-02` v2:** the agent saved `11:00` as "개장 시간" (opening time) with
  both correct evidence links. The grader expects the opening interval `11:00–17:00`.
  This is a request/grader ambiguity of the kind fixed for two tasks in `taskset-v1.1`,
  not a tool failure. Playwright happened to write the interval
  ([kitsune-benchmark#8](https://github.com/junyeong-nero/kitsune-benchmark/issues/8)).

`pb-account-01`, which failed on v0.3.1 because a seeded tab was navigated after the
snapshot lacked link URLs, passed on all three variants.

Findings:

1. **Snapshot and selector fixes (#226) show up directly.** Screenshots fell 4.4×
   (470 → 106), `find` by a third and `wait_for` by 70%. Click errors fell from 10.5%
   to 0.3%. Snapshots are larger (mean 2,627 characters) because static text and link
   URLs are back, yet total input fell.
2. **Regression: `browser_fill_form` with a checkbox fails under the default
   `KITSUNE_CAPS=core`.** 7 errors read `/api/check needs the browse capability`
   (`capability_restricted`) and 2 read `Connection reset by peer`, all on a checkbox
   field after the text fields were filled. They occurred in 9 runs (`judge-gate`
   ×6, `ui-shadow` ×3). Every run recovered by clicking the checkbox, so no task
   failed, but each paid extra calls.

   `browser_fill_form` is a core tool, and since #231 its checkbox path calls a
   route gated by `browse`. A no-model probe on a two-field form (text + checkbox)
   reproduces it: v0.3.1 fills both, while v0.4.0 fails on the checkbox
   (`Connection reset by peer`, `filled: ["name"]`). Text-only fills work. Filed as
   [kitsune#236](https://github.com/junyeong-nero/kitsune/issues/236).

   The resets have their own cause: the bridge sends caps and mode refusals before it
   reads the request body. A direct POST with a 20 KB body resets 10/10, while 2 KB
   gets the JSON refusal 10/10 ([kitsune#235](https://github.com/junyeong-nero/kitsune/issues/235)).
3. **`mm-text` refusals moved, but did not disappear.** In crowded the CAPTCHA-style
   puzzle passed 3/3 (v0.3.1: 2/3). In isolated Kitsune still did not attempt it in
   3/3, and Playwright skipped one variant too. The isolated snapshot now includes the
   "benchmark test" sentence, and Opus still declined after one snapshot. The task
   measures a refusal policy more than capability
   ([kitsune-benchmark#10](https://github.com/junyeong-nero/kitsune-benchmark/issues/10)).
4. **Collapsed rows are unreachable (since v0.3.1).** Kitsune's snapshot shows five of a
   run of similar siblings, then `- … N more similar items`. `browser_find` does not search
   the collapsed items, and scoping the snapshot to the table collapses them again. In
   `ui-table` crowded v1 the agent missed `마이크` (row 8 of page 1, stock 3), which never
   appeared in any Kitsune tool result; only a hand-written `tbody tr:nth-child(8)` shows
   it. Markers appeared in 78 of 198 Kitsune runs
   ([kitsune#237](https://github.com/junyeong-nero/kitsune/issues/237)).

## Coexistence draft (user-seeded, typing user)

Same protocol and settings as the [first coexistence run](2026-10-23-coexistence-user-seeded.md)
on v0.3.1: the user opens the starting tabs, and the shown tab is recorded throughout.

| Contract | Playwright | Kitsune v0.4.0 | Kitsune v0.3.1 |
| --- | ---: | ---: | ---: |
| v1 strict close (24 personal tasks) | 24/24 | 23/24 | 24/24 |
| v2 agent-tab cleanup | 24/24 | 24/24 | 24/24 |
| **v3 user view** | **2/24** | **23/24** | 24/24 |
| Runs where the shown tab left the starting tab | 22 | 0 | 0 |
| Starting tabs listed as agent-owned | n/a | 0 | 0 |
| Cost / MCP calls | $1.26 / 211 | $1.06 / 210 | $1.47 / 279 |

Kitsune's one v1 and v3 miss is `pb-safe-02` again: it closed its own verification
tab. The view never moved; v3 requires v1 success.

`co-typing-01`: Playwright passed v1 but failed v3. 42 of the user's keystrokes went
to other tabs, and 24 reached the journal. Kitsune passed v1 and both v3 contracts:
87 keystrokes into the journal and 0 elsewhere. Kitsune used 8 calls and $0.033;
Playwright used 8 calls and $0.071. Neither run had a tool error.

In this track Kitsune now keeps the user's view **and** costs less than Playwright,
0.84× cost at equal calls. On v0.3.1 it was 1.19× cost and 1.37× calls.

## Limits

- One attempt per task and target, fixed order, near ceiling. Differences of 1–3 runs
  are not detectable target differences.
- Kitsune v0.3.1 and v0.4.0 ran on different days in separate suites; Playwright's own
  totals moved by up to 8% between them, which bounds run-to-run noise only loosely.
- `--bare` truncates tool descriptions to their first paragraph, identically for both
  targets.
- Per-tool causes are read from transcripts. Three were confirmed by no-model probes:
  the `fill_form` checkbox regression, the early-refusal resets and the collapsed rows.
