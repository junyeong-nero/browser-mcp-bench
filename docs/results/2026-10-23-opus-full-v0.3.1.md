# Opus full suite on Kitsune v0.3.1 (taskset-v1.2)

[Results index](README.md) · [By Kitsune version](kitsune-versions.md)

**An observation, not a hypothesis verdict.** It ran every graded track once on one
Kitsune revision. Its differences can motivate issues; they are not adopted claims.

Findings, each from the run events:

1. **`browser_snapshot` omits static text and link URLs.** On the `pb-account-01`
   order page Playwright lists `paragraph: "배송 예정일: 2027-05-20"` and each link's
   `/url:`. Kitsune lists only `heading "주문 T-3"`. The agent then took a
   screenshot to read the date, and, lacking the link URL, guessed `/orders/T-3`
   (404) before navigating the seeded tab, which failed the safety check. The
   same gap plausibly drives Kitsune's 4.9× `browser_take_screenshot` and 2.2×
   `browser_find` calls. On `mm-text`, Playwright's snapshot includes the
   paragraph saying the puzzle is a benchmark test; Kitsune's does not, and Opus
   declined it as a CAPTCHA in 4/6 Kitsune runs (Playwright 1/6). Whether the
   missing sentence caused the refusals is untested.
2. **Playwright selector syntax in `target` fails as `Element not found`.** The
   published description says `target` is a ref "or a unique element selector",
   and Opus wrote Playwright locators: `text=베트남`, `role=option[name="캐나다"]`,
   `li:has-text("…") button`, `e412 >> xpath=..`, `internal:role=button[name="2"]`,
   `button:text-is("2")`. Kitsune resolves CSS only. This accounts for most of
   `browser_click`'s 30 `not_found`, `browser_hover`'s 12 and the selector errors
   of `browser_snapshot`/`browser_take_screenshot`. The error does not say that
   the syntax is unsupported.
3. **`browser_hover` does not scroll the target into view.** Playwright's hover
   does, which loads `ui-infinite`'s next page; it solved the task in ~6 calls.
   Kitsune's `hoverElement` dispatches mouse events in place, `browser_press_key
   End` goes to `body`, not the list, and the agent looped on
   `press_key`/`wait_for`/`find` (82 `browser_wait_for` calls on this task).
   CSS selectors that matched several elements failed with `ambiguous_target`
   (5×).
4. **Stale refs** (45 errors: click 21, snapshot 10, hover 7, screenshot 5, type 2).
   Refs from a `browser_find` or a partial snapshot are invalidated by the next
   snapshot. Playwright's frame-scoped refs (`f1e12`) had 1 such error.
5. **`browser_take_screenshot`**: `type: "jpeg"` is refused (4×) instead of
   falling back to PNG. Element screenshots inside the shadow DOM fail with
   `No element matches: [data-kitsune-capture-N]` (3×, `ui-shadow`). One generic
   `Screenshot failed: An unexpected error occurred`.
6. **Modifier and middle clicks can report `ok` without opening a tab.** Of 43
   `ControlOrMeta`/middle clicks, 24 reported `opened_tabs`, 13 returned `ok`
   with no tab, 6 failed. In `pb-account-01` the silent case led to the URL guess
   above.
7. **`browser_tabs` responses are thinner.** `select` returns `{"ok":true,"index":1}`,
   and `new` returns an internal `tabId` instead of the index, while
   Playwright's responses carry the tab list with `(current)`. Kitsune made 1.4×
   the tab calls, mostly re-listing.
8. **`browser_snapshot(filename=…)` saves under the server's working directory**
   (a temporary directory in this harness), which the agent cannot read.
   Playwright saves under the workspace. Once observed.

Kitsune is faster per action (`browser_click` p50 0.05 s vs 0.67 s) and returns
smaller results. Its cost disadvantage comes from the extra calls above, not from
per-call size.

## Limits

- One attempt per task and target, fixed order, near ceiling. Personal and
  isolated differences of 1–2 runs are not detectable target differences.
- `--bare` truncates tool descriptions to their first paragraph, identically for
  both targets here.
- Per-tool causes are read from transcripts. None was isolated by an intervention.
- Costs are client estimates. MiniWoB was counted at its $10 worst case in the
  suite log; its estimate was $0.06.
