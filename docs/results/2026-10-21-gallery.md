# Component gallery: modern UI, multimodal puzzles and a hand-off task

[Documentation index](../README.md) · [Reports](README.md) · [Gallery track](../gallery.md)

**Scope:** the 21 gallery tasks, variant 0, in two layouts (crowded and
isolated), one attempt per MCP, fixed order (Playwright first), 2026-10-21.
Claude Code `2.1.303 --bare` on an API key, `claude-haiku-5-5`, effort medium;
Playwright MCP `0.0.83`; Kitsune `56bd5d9` (pinned clone, clean); benchmark UI
tool allowlist. 84 agent runs, $0.54 in total.

Before any model run, a scripted reference solver passed all 126 task × variant
× layout combinations in real headless Firefox, and no multimodal answer
appears in markup or in either MCP's snapshot/page-text output.

On tasks both solved, Kitsune used **1.88× Playwright's input when isolated and

80-link header, 21 sections and a cookie banner.

Everything else passed for both MCPs:

- custom listbox, async autocomplete, tag chips, date picker, slider, modal,
  portal row menu, paginated table, infinite scroll, sortable list, the
  Steam-like review filters;
- distorted code, shape grid, chart reading;
- the owner-verification gate: both filled the form and stopped without
  attempting the verification.

## Other observations

- **kitsune#152 and #137 reproduce without the live site.**
  - `browser_find("플레이타임 필터 버튼")` returns the header's "홈", "신작",
    "인기" on the crowded page.
  - After clicking "리뷰 유형", the post-action snapshot (3,987 chars) does not
    contain the opened options.
- **`browser_dom` is unbounded.** On the crowded page it returned 128,842
  characters, over Claude Code's tool-output limit.
- **Hallucinated tool names.** In one isolated run Haiku called a non-existent
  `browser_wait`. The audit now counts such calls (`nonexistent_tool_calls`)
  instead of invalidating the trace; nothing executes.
- **Hand-off is under-used.** Both MCPs' agents stated they could not hear the
  audio, but on the crowded page neither pressed the page's "ask the user"
  button.

## Benchmark caveats

- **Wait tool asymmetry.** The UI allowlist gives Playwright `browser_wait_for`
  but omits Kitsune's `browser_wait_for`. The crowded-toast failure is partly a
  benchmark artifact; decide the allowlist before the next cohort.
- One model, one attempt, variant 0 only, fixed order: treat single-task
  differences as noise unless they repeat across layouts. Shadow DOM, iframe and
  video do repeat.
- The isolated layout's `ui-toast` and the six multimodal/judgement tasks were
  re-run after the audit fix (`ui-toast` had been invalidated by the
  hallucinated tool name). The crowded cohort ran once.
- Media playback depends on headless Firefox codec support. Playwright solved
  the video task in both layouts, so the media itself plays.
